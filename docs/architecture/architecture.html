ComplaintLens architecture

How a message from a LunaGo customer becomes an answer, which parts read which data, and where a person steps in. LunaGo is a fictional ride company; the language processing is the project.

Overview Customer journey Agent journey Full pipeline
Step or component The ride-ID rule Data that a step reads

1. Overview

Every channel feeds one API. It understands the message, checks it against the customer's record, then either answers or hands it to a person.

2. Customer journey

Anyone can write, with or without an account. A problem with a ride is answered only once we know which ride: the customer gives its ID, or picks the ride while signed in.

3. Agent journey

Agents work in the console. The inbox updates live; a conversation shows the evidence and a reply box that already holds the AI's checked suggestion.

4. Full pipeline

The complete path, with the six processing stages, the data each one reads, the five possible decisions, where each reply is delivered, and the offline research that trained and chose the models.
